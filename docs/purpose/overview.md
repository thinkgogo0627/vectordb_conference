# 원본 DB ↔ 벡터 인덱스 간극 측정 (YBIG DE 컨퍼)

## 대목적
P0: RAG·추천 시스템을 만드는 엔지니어가 원본 DB와 벡터 인덱스 사이의 간극(옛 버전이 검색되는 현상)이 언제·왜·얼마나 생기는지 알 수 있도록, 위키 편집과 커머스 상태 변경을 CDC 파이프라인으로 리플레이해 간극을 측정하고, 반영 주기와 FAISS 인덱스 구조에 따른 차이를 보여준다.

- 제약: 5인 1조, 마감 2026-12-23 (YBIG DE 컨퍼 발표). DE 트랙이라 Postgres → Debezium → Kafka 경로를 실제로 쓴다 (D-02). 실행 환경은 로컬 Docker compose. 임베딩은 bge-m3로 사전 계산해 R2에 둔다 (D-03). 벡터 저장소는 FAISS (D-01). 위키 수집기(Oracle VM)는 R2에 적재 중.
- 비목표: FAISS C++ 소스 수정, 챗봇 답변(LLM 생성) 품질 평가, 임베딩 모델 비교, Qdrant·pgvector 비교, 범용 벡터DB 제품화.
- 성공 기준: 실험 0·1·2의 그래프가 같은 리플레이 입력에서 명령 하나로 재현되고, 같은 설정 2회 실행 시 결과 차이가 허용 폭 이내다 (잠정: 허용 폭은 M0 실측 후 결정).

## 목적 계층
- P1 간극이 실제로 생긴다는 것을 측정으로 보인다 (실험 0) — 이유: 간극이 측정 가능한 크기로 존재해야 P2·P3가 의미를 가진다 / 달성 결과: 편집 후 경과 시간별 stale 비율 곡선 [확정]
  - P1.1 위키 편집을 원래 시간 순서로 Postgres에 재생 — 이유: 실시간 편집 흐름을 반복 가능하게 재현 / 달성 결과: 배속 조절 가능한 리플레이 [확정]
  - P1.2 Postgres 변경을 FAISS까지 반영하는 경로 — 이유: 원본(리더)과 벡터 인덱스(팔로워)가 분리된 구조가 간극의 원인 / 달성 결과: Debezium → Kafka → 임베딩 워커 → FAISS 경로 [확정]
  - P1.3 같은 시점 Postgres 최신과 FAISS 결과를 비교해 채점 — 이유: 정답 기준(Postgres) 대비 판정 / 달성 결과: 정상·stale·누락 판정 로그 [확정]
- P2 시간 간극: 반영 주기·배속에 따른 stale 변화와 구간별 지연 (실험 1) — 이유: 간극이 어느 구간에서 얼마나 생기고 반영 방식으로 얼마나 줄일 수 있는지 / 달성 결과: 조건별 stale 곡선 비교, 구간별(Debezium·Kafka 대기·임베딩·FAISS 반영) 지연 분해 [확정]
- P3 구조 간극: 업데이트 누적 시 인덱스 구조별 정확도·속도 변화 (실험 2) — 이유: 반영을 해도 인덱스 구조 때문에 검색이 나빠지는 간극이 따로 있다 / 달성 결과: 누적 업데이트 대비 recall@10·p95·구버전 혼입률 그래프, 인덱스별 재구축 주기 [확정]
  - P3.1 위키: 버전 교체 시 Flat / IVF / HNSW+꺼둔 노드 비교 — 이유: 본문이 바뀌는 데이터 [확정]
  - P3.2 커머스(Retailrocket): 품절·재입고를 꺼둔 노드 / 지웠다 다시 넣기 / 재구축으로 비교 — 이유: 상태가 켜졌다 꺼지는 데이터 [확정]
  - P3.3 FAISS 위 정책(꺼진 비율 기준 재구축 트리거, 탐색 폭 자동 조절 등)으로 재구축 주기 개선 — 이유: 측정에서 끝나지 않고 개선안 제시 [미결: 2026-12-07에 착수 여부 결정 (D-05)]

## 미결·가정
- [가정] R2 위키 데이터에 편집 본문이 있다 → 확인 방법: T-01 (사용자)
- [가정] Postgres + Debezium + Kafka compose 구성이 반나절 안에 된다 → 확인 방법: T-03. 하루 초과 시 임시 폴링 (D-02)
- [가정] 간극이 측정 가능한 크기로 존재한다. 단, 간극의 상당 부분이 주입한 embed_ms에서 올 수 있다 (GR-03) → 확인 방법: T-07
- [가정] FAISS HNSW는 remove를 지원하지 않고, IDSelector로 걸러낸 노드도 탐색 중 경유한다 → 확인 방법: M1 초반 코드·문서 확인
- [가정] 작은 수정 위주 위키 데이터에서 IVF 중심점 노후화 효과가 작을 수 있다 → 확인 방법: M1 IVF 파일럿
- [미결] P3.3 착수 여부 → 결정: 사용자(팀장), 2026-12-07
